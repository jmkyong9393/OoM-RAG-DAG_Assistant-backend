# OoM Assist — 백엔드

직원의 업무 질문에 **회사 규정 조문**과 **부서가 과거에 해결한 사례**를 근거로 답하는 어시스턴트의 백엔드입니다. 답변의 문장마다 근거 번호가 붙고, 그 근거가 실제로 검색된 것인지 서버가 확인합니다.

**Spring Boot · Python FastAPI · PostgreSQL(pgvector)** · 프론트엔드 [OoM-RAG-DAG_Assistant](https://github.com/Jonghyeon-Bae/OoM-RAG-DAG_Assistant) · 운영 서버 한 대에 무중단 자동 배포

## 무엇을 하나

| 기능 | 한 줄 |
|---|---|
| 규정 검색 | 형태소 어휘 + 벡터 검색을 합친 뒤 가벼운 모델이 다시 골라, 구어체 질문에서도 맞는 조문을 찾는다 |
| 사례 체인 | 문제 → 원인 → 해결 기록을 그래프(DAG)로 엮고, 질문과 같은 문제를 다룬 체인을 답변에 싣는다 |
| 규정 ↔ 사례 | 사례마다 "규정을 따름 · 달리 처리 · 기준 없음"을 기록해 답변이 그 관계를 함께 말한다 |
| 인용 검증 | 근거 표시(`[P1]` 규정 · `[N3]` 사례)를 검색 결과와 코드로 대조해 스트리밍(SSE)으로 보낸다 |
| 규정 관리 | PDF · Word · 한글 업로드 → 조문 변환 → 검수 · 승인, 개정되면 영향받는 사례를 조문 단위로 대조 |
| 장애 보고서 | 경과 · 원인 · 조치는 기록 그대로, 요약 문장만 AI 가 근거 번호와 함께 쓴다 |
| 계정 · 권한 | 사번 로그인 · 서버 세션, 회사 > 부서 권한, 잠금 · 비활성화 · 접속 기록 |

## 얼마나 잘 되나

가상의 두 회사(유통 · IT 서비스)의 규정 38종(조문 1,425개)과 사례 284건으로 잽니다.

| 측정 | 결과 |
|---|---|
| 검색 hit@5 (질문 740건) | **0.988** · MRR@5 0.875 |
| 답변 — 처음 보는 질문 20개 블라인드 비교 | 지금 버전 나음 **10** · 이전 버전 5 · 같음 5 |
| 답변 충실도 (48문항) | **0.95** — 문장 161 / 169 가 근거로 뒷받침 |
| 첫 글자까지 (운영 서버) | 중앙값 **2.7초** |
| 배포 중 요청 실패 (운영 서버, 두 번) | **0건** — 요청 1,795 · 채팅 97 |

- 2026-11-20 ~ 24 측정. 답변 모델은 `gpt-4o-mini` 그대로 두고, 모델에 넣는 근거 · 지시와 사례 선택으로 품질을 올렸습니다.
- 답변 개선은 고치는 데 쓴 질문이 아니라, **고치기 전에 해시로 봉인한 질문**의 블라인드 비교로 판정합니다(`eval/holdout.py`).

## 구조

```
브라우저 ─ Caddy(HTTPS) ─┬─ /          ▶ web   Next.js (프론트 레포)
                         └─ /api/v1/*  ▶ api   Spring Boot · 인증 · 권한 · 기록 · 문서 · 보고서 · SSE 중계
                                          └▶ ai  FastAPI · 분류 → 규정 ∥ 사례 검색 → 답변 → 인용 검증 (+ 정제 워커)
                                     PostgreSQL 16 + pgvector — 검색 · 체인 조회는 DB 함수로 두 서비스가 공유
```

| 고른 것 | 이유 |
|---|---|
| DB 하나(pgvector + 재귀 질의) | 벡터 · 그래프 DB 를 따로 두지 않아 검색 · 체인 · 트랜잭션이 어긋나지 않는다 |
| 인용은 코드가 확인 | AI 를 한 번 더 부르지 않아 빠르고, 비용이 없고, 결과가 매번 같다 |
| 사실과 AI 문장 분리 | 보고서의 사실은 서버가 기록에서 조립하고 AI 는 요약만 — 기록에 없는 원인을 지어내지 않는다 |
| 기록은 자료로만 | 직원이 쓴 기록 원문은 경계 태그로 감싸, 그 안의 지시 문장을 따르지 않는다 |

## 빠른 시작

Docker · Java 21 · [uv](https://docs.astral.sh/uv/) 가 필요합니다(Windows 는 Git Bash · WSL).

```bash
cp deploy/.env.example deploy/.env      # 로컬 기본값으로 바로 동작
make up migrate seed index              # PostgreSQL · 스키마 · 시드 · 규정
make api                                # :8080 (다른 터미널)
make ai                                 # :8000 (다른 터미널)
make load-logs && make worker ARGS=--once && make link-policies link-chains   # 사례 · 정제 · 근거 연결
```

- 계정: 유통 `OOM0001` ~ `0005`, IT `OIT0001` ~ `0005`(0001 이 회사 관리자). 비밀번호는 `deploy/.env` 의 `SEED_PASSWORD`.
- AI 키(`LLM_PROFILE_DEFAULT_API_KEY`)가 없으면 검색은 실제로 하고 답변은 규칙으로 만든 흉내 답변이 나옵니다.
- 적재 명령은 다시 돌려도 결과가 같습니다(`make seed-reset` 만 업무 테이블을 비웁니다).
